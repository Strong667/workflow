# Обновление до PrimeVue 5

Проект работает на **PrimeVue 4.5.5 (MIT)** и подготовлен к переходу на 5.
Обновление проверено на практике: с установленными `primevue@5.0.1`,
`@primeuix/themes@3.0.0` и `primeicons@8.0.0` проект проходит `vue-tsc`
и `vite build` **без единой правки в коде**, а в браузере корректно
отрисовываются таблицы, графики и тёмная тема.

## Что нужно сделать

```bash
cd frontend
npm run upgrade:primevue5    # ставит primevue@5, @primeuix/themes@3, primeicons@8
npm run type-check && npm run build
```

После этого — зарегистрировать лицензионный ключ (см. ниже).

## Лицензия — единственное настоящее препятствие

Начиная с версии 5, PrimeVue и PrimeIcons распространяются по лицензии
PrimeUI. Community-тариф бесплатен для частных лиц, студентов, НКО и
компаний с выручкой до $1 млн, штатом до 10 человек и объёмом внешних
инвестиций до $3 млн, но **требует зарегистрированного ключа** и
ежегодного подтверждения права на бесплатный тариф.

Без ключа приложение работает, но в консоль пишется
`[PrimeUI] PrimeUI license is not configured`.

Ключ регистрируется один раз при старте приложения — в `src/main.ts`,
до `app.use(PrimeVue, …)`:

```ts
import { registerLicense } from '@primeui/license-manager'

registerLicense({ primeui: import.meta.env.VITE_PRIMEUI_LICENSE })
```

Ключ хранится в `frontend/.env` (файл не коммитится):

```
VITE_PRIMEUI_LICENSE=<ключ с primeui.dev>
```

Проверка лицензии выполняется офлайн, без обращений к сети.

## Почему обновление обходится дёшево

Весь код, знающий о библиотеке, собран в `frontend/src/ui/`:

| Файл | Что придётся править при мажорном обновлении |
| --- | --- |
| `theme.ts` | если поменяется формат пресета или опций плагина |
| `global-components.ts` | если переименуют глобально регистрируемые компоненты |
| `lazy-components.ts` | если переименуют тяжёлые компоненты — пути лежат только здесь |
| `locales.ts` | если добавятся новые ключи подписей |
| `tokens.ts` | уже умеет читать и обычные цвета, и запись `light-dark()` из v5 |
| `feedback.ts` | если изменится API уведомлений или диалога подтверждения |

Экраны обращаются к библиотеке только через этот каталог, поэтому
переименование компонента правится в одном месте, а не в 30 файлах.

## Отличия v5, которые уже учтены

1. **Токены темы в формате `light-dark()`.** В v4 `--p-primary-500`
   возвращает обычный цвет, в v5 — `light-dark(#6366f1, #818cf8)`.
   Chart.js такую запись не понимает и рисует график дефолтным цветом.
   `src/ui/tokens.ts` отдаёт значение, вычисленное браузером, и работает
   с обеими версиями.

2. **Имена компонентов.** Проект уже использует имена, принятые в v4/v5
   (`Select`, `DatePicker`, `ToggleSwitch`), а не устаревшие
   `Dropdown`, `Calendar`, `InputSwitch`.

3. **Пакет тем.** Используется `@primeuix/themes` (в v4 — второй мажор,
   в v5 — третий); импорты `@primeuix/themes/aura` и `definePreset`
   в обеих версиях одинаковы.

## Откат

```bash
npm run downgrade:primevue4
```
